1. What the backend is missing

Things the server must add, fix or switch on so the app can finish its screens. Each item says what is wrong, why it matters, and what we ask for. They are grouped from "affects real users now" to "cannot test yet".

A. Problems that affect real users today

No full mock exam can be started: the question bank is missing question types

What is wrong
Starting a full paper fails with error 503 for all three exams (tested on staging today). CAT: "VARC is 16 reading comprehension + 8 verbal ability; verbal ability: needs 8, the pool has 0". GMAT: the Verbal section "cannot run as a scored mock" because the questions carry no question type or passage id. GRE: the Verbal section cannot run because there is no "select two" question type, so sentence equivalence and multi-blank questions cannot be served. Only a labelled practice version works (asking with practice: true gave CAT: 24 + 20 + 22 questions), and CAT sectional DILR also worked.
Why it matters
Users who tap a full mock paper see an error. The app now explains it and offers "Take it as practice", but a real, scored full mock cannot be taken, and practice attempts do not count toward the percentile.
What we ask
Add verbal-ability questions to the bank (para jumble, para summary, odd sentence out, at least 8 for CAT), add question type and passage id to the GMAT questions, and add a "select two" question type for GRE. Or tell us which papers should be offered as practice only.
Screens affected
Learn > Mock exam

Nobody can pay: no payment provider is set up

What is wrong
The plans list says no payment provider is available ("providers_available" is empty). Because of this, the checkout, verify, cancel, resume and change-plan routes cannot be used.
Why it matters
Users can see Pro and Bundle prices but cannot buy them. Family seats (child accounts) also need a paid plan, so they cannot be created either.
What we ask
Set up Razorpay (and/or Stripe) on staging in test mode, and tell us which one and which currency to use. Also decide: monthly only, or monthly and yearly (the plans have monthly prices only).
Screens affected
Upgrade pop-up, Family page

The server never learns a user's age

What is wrong
The app asks for date of birth during onboarding and saves it. But the server only keeps it inside the profile text; the user's real "age" field stays empty. The only accounts that get an age are child seats made from the Family page (we read this in the server code).
Why it matters
The server then treats every normal user as "age unknown". We checked: the test account says age_known: false. As the code stands, the ads rule needs a known age, so ads cannot show for anyone, and child-safety rules cannot be applied to a real child who signs up alone.
What we ask
When a date of birth is saved, work out and store the age. Or tell us another way to set it.
Screens affected
Onboarding, ads, friends, clubs, tournaments

Exam topic lists use made-up numbers and names that have no questions

What is wrong
Asking for topics for an exam (for example CAT) returns five names typed into the code, like "Quantitative Aptitude". The numbers next to them (25 problems, 4 subtopics) are a default, not a real count. We tested: asking the practice route for "Quantitative Aptitude" returns zero questions.
Why it matters
The Explorer shows these names and counts, but they cannot be practised, and the counts are not true.
What we ask
Link each exam topic to real topics or skills with true counts, or return a clear "no content yet" for it.
Screens affected
Explorer (Topics tab)

Practice cannot be limited to one sub-topic

What is wrong
The new route /api/topics/{topic}/subtopics works well (names and problem counts, for example Algebra has "Polynomial Factorization": 5 problems). But the practice route can only filter by topic and technique, not by sub-topic.
Why it matters
A user can see sub-topics but cannot practise one.
What we ask
Let the practice route accept a sub-topic (the problems already store one).
Screens affected
Explorer, Technique page

Study cards are not linked to practice skills, and most are not finished

What is wrong
There are 44 study cards. Only 2 are finished (Nikhilam Sutra and Urdhva-Tiryakbhyam); 42 are waiting for review. Nothing tells us which practice skill belongs to a card. Result: the Urdhva card has no practice skill at all in the practice list.
Why it matters
The technique page can only show real content for 2 cards, and its Practice buttons only work when a skill happens to have the same name.
What we ask
Add the matching practice skill to each study card (or the other way round), and finish and approve the remaining cards.
Screens affected
Technique page, Explorer

Clubs lack the details the design shows

A club only has a name, type, city and member count. There is no moderator, picture, description, tags or last-activity time. Members can only be seen through the weekly leaderboard.
Why it matters
Club cards look plain compared with the design.
What we ask
Add the fields the product wants, or tell us the design should be simplified.

Clubs

Profile saving is too loose

What is wrong
Gender, goal and persona accept any text. Date of birth accepts any shape. Sending only a name overwrites the first name. The answers are kept in one text block and the reply is not described.
Why it matters
Wrong values are stored without an error and cannot be relied on later.
What we ask
Check values (reject wrong ones with a clear error), keep the first name when only the name is sent, and describe the reply shape.
Screens affected
Onboarding, Profile

Delete account: confirm what is erased

What is wrong
The route is live and deletes the user and their attempt tables.
Why it matters
We need to be sure login tokens, friends, subscriptions, device sessions and any stored files are removed, and that the old token stops working.
What we ask
Confirm the full list of what is deleted, and describe the reply.
Screens affected
Settings > Delete account

Referral wording does not match what the server does

What is wrong
The invite card says a friend gets 50 bonus XP. When a friend uses the code the server records it and gives nothing at that moment; rewards come later from the ladder (15, 30, 45, 60 verified friends).
Why it matters
Users may expect XP that never arrives.
What we ask
Tell us the correct promise, or give the XP when the code is used.
Screens affected
Dashboard invite card

Clubs are available as /clubs and as /hub (identical). The feed is at /api/v1/feed, /api/feed and /feed, but the plain /feed address answers "not found" from outside.

Pick one official name for each and tell us. We use /clubs and /api/v1/feed today.
Screens affected
Clubs, Feed

2. What the frontend is missing

Our side of the work, and a check of every page in the app.

2.1 Screens we cannot finish until the backend adds something

  • Duel (live match). Waiting on the backend: simple routes or a written game-message guide.
  • Class Calendar. Waiting on the backend: planner routes.
  • Linked devices. Waiting on the backend: device list and sign-out routes.
  • Real notifications. Waiting on the backend: read state and push registration.
  • Buying a plan. Waiting on the backend: a payment provider. We will build the whole flow (choose plan, pay, verify, cancel, resume, change) once one is set up, and test only with test-mode keys.
  • Tournaments screen. Waiting on the backend: the feature is off and there is no list route.
  • Check-in at a club, video clips, beta feedback form. Waiting on the backend: these features are switched off.

2.2 Screens we can build now (the server is ready, the app is not)

  • Daily challenge. The server is ready (today's 10 problems, submit your score, leaderboard). We have not built the screen.
  • Race a ghost. The server is ready (save a run, race it). We have not built the screen.
  • Kids and safety rules from the server. The policy route works. The app does not read it yet, so it cannot hide features for a child or show a session limit.
  • Real sub-topic counts. The new sub-topics route gives real problem counts per sub-topic. The Explorer does not use it yet.
  • Chat usage and budget. The route works. The app does not show the daily hint budget.
  • Ads without a connection. The route that gives ads to keep offline is not used. Without internet, no ad is shown.
  • Beta code at sign-up. The server accepts an invite code at registration and after. The app has no place to type it (the feature is off, so low priority).

2.3 Things on our side that are wrong or unfinished

  • Sprint difficulty does nothing. The Beginner / Advanced choice on Configure Sprint is not used when the session starts. The server can aim at a difficulty level, so we can make it real.
  • Learn cards on Configure Sprint are built-in lessons. They are written inside the app, not from the server. They should come out or be replaced.
  • Solve-along lessons are built-in. The step-by-step lessons in practice come from the app files, not the server.
  • Share invite shares the code, not the link. The Share button sends the text with the code but not the link that records the referral.
  • Google and phone sign-in buttons. They lead to "not set up". They should say so or be hidden until the backend is ready.
  • Sign-in token is stored in plain browser storage on Android. It should move to secure storage on the phone (needs a plugin).
  • Android app is not tested on a phone. The APK built earlier today was never installed and does not include the later work (ads, feed, club details, hints, referral claim). The camera scan, onboarding save, clubs and delete account all still need a real-device check on a new build.
  • Live checks with real data. Saving onboarding and logging in again, creating a club, delete account, friend QR, referral claim: tested with fake data only. They need a run on a test account.
  • Production build check. The build with the new technique pages (one page per study card id) has not been run.
  • 12 old tests fail. They are in the onboarding intro carousel, stall timer and review carousel. They are old and not caused by recent work, but they should be fixed.
  • Small "Coming soon" rows. Settings still has rows named Call Reminder and Payments marked Coming soon.
