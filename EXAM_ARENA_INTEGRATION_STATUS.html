What the frontend does and what the backend must do

AreaFrontend responsibility (done or in the code)Backend responsibility (open)
TokensOne refresh per expiry; offline never logs out; real rejection clears local data.None open. Tokens are healthy (HS256, 15 min, rotation with reuse detection).
OnboardingHydrate from /auth/me; save with PATCH; complete only after 2xx; never send empty values.Define null/empty semantics, validate enums, stop storing answers in behavioral_profile.
MasterySends attempt events and refreshes caches after a confirmed sync.Compute mastery from attempts (or ship the BKT engine).
Exam-specific contentLabels everything global; switch ready behind one flag.Exam tag and filter on topics, skills and catalog.
Missing modulesHonest unavailable states; no fabricated data in real mode.Planner, linked devices, notifications, feed, club fields, duel protocol.

Mock and local-only functionality

  • Mock fixtures load only when NEXT_PUBLIC_API_MOCK=true; real mode never falls back to them.
  • Bundled, non-user content: help FAQ, technique lesson text, solve-along templates (authored content, not account data).
  • Local-only user data (no backend field): date of birth detail beyond dob, exam dates, reminder and focus settings, plan lane, habit tracking, theme.
  • Profile edit page saves locally only.

Web and Android

  • Web: production build passes; reads verified against staging from a script. Browser-level end-to-end runs with a signed-in session were not performed in this pass.
  • Android APK: a debug APK was built earlier from the staging configuration. It was not rebuilt for this pass and not tested on a device. Web success does not prove APK compatibility.
